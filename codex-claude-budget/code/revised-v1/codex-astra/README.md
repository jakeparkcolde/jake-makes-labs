# 차곡 · CSV 가계부

외부 API, 패키지, CDN 없이 HTML/CSS/JavaScript로 실행하는 한국어 가계부입니다. CSV는 브라우저에서 읽으며 외부로 전송하지 않습니다. 제공된 두 입력 파일은 수정하지 않았고, 변경 전후 SHA-256 일치를 확인했습니다.

## 실행

`index.html`을 브라우저로 열면 바로 실행할 수 있습니다. 새로고침 후 저장을 일관되게 사용하려면 로컬 HTTP 실행을 권장합니다. `file://` 저장 동작은 브라우저마다 다릅니다.

Python 3가 있는 환경에서 이 프로젝트 폴더를 현재 디렉터리로 두고 실행합니다. 패키지 설치는 필요하지 않습니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

1. `http://127.0.0.1:8000`에 접속합니다.
2. **CSV 파일 선택**으로 `inputs/01-basic.csv`를 가져옵니다. 최초 화면에서는 드래그 업로드도 가능합니다.
3. **CSV 추가 가져오기**로 `inputs/02-refunds-and-duplicates.csv`를 가져옵니다. 기존 기록에 새 ID만 추가하며, 현재 선택한 월을 유지합니다. 변경 파일부터 가져와도 됩니다.
4. **최근 가져오기 결과**에서 추가·중복·환불 건수를 확인합니다. 펼침 영역에서 제외된 각 레코드의 번호·ID·내용·제외 이유, 이번에 반영된 환불과 원거래 참조를 확인할 수 있습니다. 이 영역은 월 필터와 무관하며 최근 파일 1개의 결과만 표시합니다.
5. **조회 기간**으로 전체 또는 월을 고릅니다. 요약·차트·목록·CSV 내려받기에 동일한 기간을 적용합니다. ‘전체 누적 순지출’은 별도로 전체 데이터의 합계를 표시합니다.
6. **CSV 내려받기**로 현재 기간의 고유 거래를 UTF-8 CSV로 저장합니다.
7. 서버 종료는 터미널에서 `Ctrl+C`입니다. 이번 작업에서 백그라운드 서버를 실행하지 않았습니다.

## 병합·환불 규칙

- 중복 기준은 `transaction_id` 하나입니다. 기존 거래를 우선 보존하며, 새 ID가 파일 안에 여러 번 나오면 첫 레코드만 추가합니다. 같은 ID의 내용이 다르더라도 덮어쓰지 않고 중복 상세에 내용 차이를 표시합니다.
- 날짜·가맹점·금액이 같아도 ID가 다르면 별개 거래입니다. `S05`와 `S09` 모두 포함됩니다.
- `amount_krw`의 부호를 그대로 더합니다. **순지출 = 지출 합계 + 음수 환불 합계**입니다. 환불 합계 카드·거래 목록·CSV에서도 음수를 유지하며 다시 빼지 않습니다.
- 원래 결제와 환불은 서로 다른 ID로 각각 보존합니다. 월별 집계는 각 레코드의 `date` 기준입니다. 다른 달의 원결제를 참조해도 환불 날짜의 월에 합산합니다.
- `original_transaction_id`는 확인용 참조입니다. 거래 목록 및 환불 상세에서 원거래를 찾아 날짜·가맹점·금액을 보여 줍니다. 참조가 없거나 저장된 결제에서 찾을 수 없어도 환불을 그대로 반영하고 해당 상태를 표시합니다. 금액 상계나 원거래 삭제에 사용하지 않습니다.
- 같은 파일, 이미 내보낸 파일, 과거 기본 파일을 다시 가져와도 저장된 ID는 재반영하지 않습니다. 재업로드 시 ‘이번에 반영한 환불’은 0건이지만 기존 환불은 거래 목록에 유지됩니다.
- 파일 전체를 검증한 뒤 병합합니다. 잘못된 파일은 기존 거래·월·최근 가져오기 결과를 변경하지 않습니다.

## CSV 형식

- UTF-8 CSV를 사용합니다. BOM, LF/CRLF, 따옴표로 감싼 쉼표·줄바꿈·이스케이프된 따옴표를 처리합니다.
- 필수 열: `transaction_id,date,merchant,category,amount_krw,type`
- 선택 열: `original_transaction_id`. 열 순서는 자유이며 추가 열은 무시합니다.
- 날짜는 실제 존재하는 `YYYY-MM-DD`, 금액은 쉼표·통화 기호 없는 원 단위 정수입니다. `expense`는 0 이상, `refund`는 0 이하입니다. 양수 환불 CSV는 오류로 안내하며 임의로 부호를 바꾸지 않습니다.
- 개별 금액과 중복 제외 후 병합된 거래의 금액 절댓값 합계가 JavaScript 안전 정수 범위를 넘으면 거부합니다.
- 빈 파일, 거래 없는 파일, 필수 열·값 누락, 잘못된 날짜·금액·유형·따옴표, 열 수 불일치는 이해할 수 있는 오류로 안내합니다.
- 거래는 날짜 내림차순이며 같은 날짜는 먼저 가져온 순서를 유지합니다.
- 카테고리 차트는 같은 기간의 부호 있는 금액 합계입니다. 막대 길이는 최대 절댓값에 비례하며 음수 순지출은 ‘환불 초과’ 문구로 구분합니다.
- 내보내기는 현재 필터의 고유 거래를 위 7개 열, UTF-8 BOM, CRLF로 저장합니다. 금액의 음수 부호·거래 ID·원거래 참조를 보존합니다. 추가 열과 셀 앞뒤 공백은 보존하지 않습니다.

## 브라우저 저장과 이전 버전

같은 브라우저 프로필과 같은 주소·포트를 사용하면 거래·선택한 월·최근 파일명·최근 가져오기 결과를 복원합니다. 기존 `localStorage` 키 `chagog.ledger.v1`을 계속 사용하며, 내부 데이터 형식은 `version: 2`입니다.

1라운드의 `version: 1` 저장 데이터도 읽습니다. 이전 버전이 저장한 양수 환불이 있다면 저장 형식 이관에서만 음수로 바꾸고, 기존 기본 거래와 월 선택은 보존합니다. 이후 버전 2로 저장하여 반복적으로 부호가 바뀌지 않습니다. 새 CSV에는 이 변환을 적용하지 않습니다.

비공개 모드 종료, 사이트 데이터 삭제, 저장 차단·용량 초과 시 기록이 유지되지 않을 수 있습니다. 저장 실패는 화면에 안내하며, 이 경우 새로고침하면 이전에 저장된 상태로 돌아갈 수 있습니다. 최근 가져오기 결과는 1개만 보관하며 전체 가져오기 이력은 제공하지 않습니다.

```sh

node --test tests/ledger.test.js
```

## 미검증 항목과 한계

**실제 브라우저 조작 검수는 이번 단계에서 수행하지 않았습니다.** 코드 검사는 화면 렌더링·실제 저장·다운로드 성공을 보장하지 않습니다. 후속 공통 절차에서 확인할 항목:

- 파일 선택·드래그, 병합 결과 펼침, 중복 사유와 환불 원거래 참조 표시.
- 월 필터 변경 시 카드·차트·목록·내려받기 범위가 함께 바뀌는지.
- 같은 주소에서 새로고침 후 거래·월·최근 가져오기 결과가 복원되는지. 저장 복원 함수와 JSON 왕복은 검사했지만 실제 브라우저 `localStorage`는 미검증입니다.
- 음수 금액이 한 번만 표시되는지, 실제 다운로드의 한글 파일명·UTF-8 내용과 재업로드.
- **390px 폭**에서 가로 넘침, 긴 가맹점·ID·참조 문구, 결과 목록 스크롤, 버튼 조작성. 기존 반응형 레이아웃을 유지하고 새 결과 영역에 줄바꿈을 적용했으나 시각 검수는 미실시입니다.
- 키보드 포커스, 상태·오류 안내의 스크린리더 전달, 브라우저별 호환성.

현대적인 브라우저의 File API, TextDecoder, Blob, BigInt, localStorage를 사용합니다. 대용량 파일은 전체를 메모리와 DOM에 올리므로 처리 속도·저장 용량에 한계가 있습니다. 수입·이체·다른 통화, 다중 탭 실시간 동기화, 거래 편집은 지원하지 않습니다. 필요한 기록은 CSV로 별도 보관하세요.

## 파일 구성

- `index.html`: 업로드 안내·가계부·최근 가져오기 결과
- `styles.css`: 데스크톱·모바일 화면
- `ledger.js`: CSV 입출력·검증·병합·필터·합계·저장 데이터 복원
- `app.js`: 화면·파일 선택·브라우저 저장·다운로드 연결
- `tests/ledger.test.js`: 외부 패키지 없는 기능 검사
- `verification/round2-results.json`: 이번 시나리오 직접 실행 결과
- `inputs/01-basic.csv`, `inputs/02-refunds-and-duplicates.csv`: 제공된 원본 샘플
