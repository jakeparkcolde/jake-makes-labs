# 같은 가계부

CSV 거래 내역을 올리면 전체·월별 순지출, 카테고리별 합계와 차트, 거래 목록을 보여주는 한국어 웹 가계부입니다.
HTML/CSS/JavaScript만 사용하며 외부 패키지·외부 API·서버가 필요 없습니다. 데이터는 브라우저 밖으로 나가지 않습니다.

## 실행 방법

가장 간단한 방법은 `index.html`을 브라우저에서 직접 여는 것입니다.

```
open index.html          # macOS
```

파일(`file://`)로 열어도 동작하도록 ES 모듈을 쓰지 않았습니다. 로컬 서버로 열고 싶다면 (Python 3 내장 모듈, 설치 불필요):

```
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000/ 접속
```

앱을 열고 `inputs/01-basic.csv`를 끌어다 놓거나 눌러서 선택하면 됩니다.
그 다음 상단의 "CSV 추가로 올리기"(또는 대시보드 아무 곳에나 끌어다 놓기)로 `inputs/02-refunds-and-duplicates.csv`를 올리면 기존 데이터에 병합됩니다.

## 코드 검사

```
node tests/ledger.test.js     # 파서·병합·집계·내보내기 단위 테스트 (20개)
node tests/scenarios.js       # 실제 입력 파일로 세 가지 가져오기 시나리오 결과 출력
node tests/static-check.js    # app.js 가 참조하는 id/클래스가 HTML/CSS 에 있는지 확인
node --check js/ledger.js js/app.js
```

현재 결과: 단위 테스트 20개 통과, 정적 검사 통과, 문법 검사 통과.

## 파일 구성

| 경로 | 역할 |
|---|---|
| `index.html` | 화면 구조 (업로드 화면 + 대시보드 + 가져오기 결과 카드) |
| `css/style.css` | 스타일. 390px 모바일 대응, 다크 모드(OS 설정) 대응 |
| `js/ledger.js` | 순수 로직: CSV 파싱, 열 인식, 검증, ID 기준 병합, 집계, CSV 내보내기, 금액 형식. DOM 의존 없음 (Node에서도 로드 가능) |
| `js/app.js` | 화면 렌더링, localStorage 저장, 파일 읽기, 월 필터, 내려받기, 가져오기 결과 표시 |
| `tests/` | Node 로 실행하는 검사 스크립트 |
| `inputs/01-basic.csv`, `inputs/02-refunds-and-duplicates.csv` | 샘플 입력 (수정하지 않음) |

## 동작 규칙

- **필수 열**: `date`, `merchant`, `category`, `amount_krw`. 선택 열: `type`, `transaction_id`(권장), `original_transaction_id`.
  한글 열 이름(날짜·가맹점·분류·금액·유형 등)과 `amount` 같은 별칭도 인식합니다. 첫 줄은 열 이름이어야 합니다.
- **병합과 중복 제거**: 파일을 올리면 기존 데이터에 병합합니다. 중복 기준은 `transaction_id`이며 같은 ID는 한 번만 반영합니다
  (먼저 들어온 거래가 남습니다). 같은 날짜·가맹점·금액이라도 ID가 다르면 별개 거래입니다. 파일 안에서 같은 ID가 반복돼도 한 번만 반영합니다.
  같은 파일을 다시 올리면 추가 0건으로 처리되어 거래 수와 합계가 바뀌지 않습니다.
- **ID 열이 없는 파일**: 날짜·가맹점·분류·금액·유형으로 내용 기반 ID를 만듭니다. 같은 파일을 다시 올리면 중복으로 제외되고, 내용이 같은 행이 여러 개면 순번을 붙여 별개 거래로 봅니다. 경고를 표시합니다.
- **순지출** = 지출(`expense`)과 환불(`refund`) 금액을 파일의 부호 그대로 합한 값. 환불은 `amount_krw`가 이미 음수이므로 다시 빼지 않습니다.
  `type`이 비어 있으면 지출로 봅니다. `income`·`transfer` 등 다른 유형은 목록에는 표시하되 순지출에서 제외하고 "제외" 배지를 붙입니다.
- **환불 표시**: 원래 결제와 환불을 각각 한 건씩 보존합니다. 월별·카테고리별 합계는 각 거래의 `date` 기준입니다.
  거래 목록에서 환불 행에는 "환불 · 원거래 S06" 배지, 원거래 행에는 "환불됨 · R01" 배지가 붙습니다. `original_transaction_id`는 참조용이며 합계 계산에는 쓰지 않습니다.
- **가져오기 결과 카드**: 마지막 가져오기의 읽은 행·추가·중복 제외·환불 반영 건수를 보여주고, "중복으로 제외한 행 보기"(행 번호·ID·내용·이유)와
  "반영한 환불 보기"(환불 금액과 원거래 정보, 원거래를 못 찾으면 경고)를 펼쳐 볼 수 있습니다. 가져온 파일 기록도 최근 10건까지 남깁니다.
- **월 필터**: 전체 기간 또는 특정 월. 바꾸면 요약 숫자, 카테고리 차트, 거래 목록이 같은 범위로 바뀝니다.
  월별 순지출 차트는 항상 전체 기간을 보여주고 선택한 달을 강조하며, 막대를 눌러 그 달로 이동할 수 있습니다.
- **저장**: 병합된 거래와 가져오기 기록을 localStorage(`gagyebu.v2.data`), 선택한 월을 `gagyebu.v1.month`에 저장해 새로고침해도 유지됩니다.
  1라운드 형식(`gagyebu.v1.data`)이 남아 있으면 자동으로 옮깁니다. "데이터 지우기"로 삭제합니다.
- **내려받기**: 현재 필터에 해당하는 거래를 UTF-8(BOM 포함) CSV로 저장합니다. 파일명은 `가계부_전체.csv` 또는 `가계부_YYYY-MM.csv`.
  열 순서는 샘플과 같고 환불은 음수 금액과 `original_transaction_id`를 그대로 씁니다:
  `transaction_id,date,merchant,category,amount_krw,type,original_transaction_id`.
- **오류 처리**: 빈 파일, 열 이름만 있는 파일, 필수 열이 없는 파일, 모든 행이 잘못된 파일은 원인을 설명하는 메시지를 보여줍니다.
  일부 행만 잘못된 경우 그 행은 건너뛰고 행 번호와 이유를 대시보드 상단에 표시합니다. 대시보드 상태에서 실패하면 기존 데이터는 유지됩니다.
- **인코딩**: UTF-8을 우선 시도하고, 실패하면 EUC-KR(CP949)로 다시 읽습니다.

## 아직 브라우저에서 확인하지 못한 사항

이 단계에서는 브라우저를 실행할 수 없어 아래는 코드 검토와 Node 테스트로만 확인했습니다. 실제 브라우저 검수가 필요합니다.

- 파일 선택·끌어다 놓기·FileReader 흐름, 대시보드 상태에서 두 번째 파일을 올려 병합되는 과정과 토스트 문구
- 가져오기 결과 카드의 `<details>` 펼침, 중복 행·환불 목록의 줄바꿈(특히 390px 폭)
- 거래 목록의 환불 배지·"환불됨" 배지 배치, 환불 행의 옅은 배경
- 390px 폭 레이아웃(통계 카드 2열 배치, 분류 열이 가맹점 아래로 내려가는지, 막대 라벨 잘림 여부)
- localStorage 저장·복원, 1라운드 저장 형식에서의 자동 이전, 새로고침 후 월 선택 유지
  (브라우저의 `file://` 저장소 정책에 따라 다를 수 있음. Safari에서 문제가 있으면 위의 로컬 서버 방식으로 여세요)
- CSV 내려받기 버튼의 실제 저장 동작과 한글 파일명, 다크 모드 색상, 막대 차트의 hover 제목(툴팁)

## 한계

- 자동 테스트는 순수 로직(`ledger.js`)만 다루며 DOM 동작은 검사하지 않습니다.
- 같은 ID인데 내용이 다른 행이 들어오면 먼저 있던 거래를 유지하고 새 행은 중복으로 보고합니다. 내용 비교나 덮어쓰기 기능은 없습니다.
- 환불 금액이 양수로 적힌 파일은 부호 그대로 더하므로 순지출이 늘어납니다(요구 규칙에 따라 부호를 바꾸지 않음).
- 대용량 파일은 20MB까지만 받습니다. 거래 목록은 가상 스크롤 없이 모두 그리므로 수만 건이면 느려질 수 있습니다.
- 날짜는 `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD`, `YYYYMMDD`, `YYYY년 M월 D일` 형식만 인식합니다. `MM/DD/YYYY`는 인식하지 않습니다.
- 카테고리는 파일에 적힌 값을 그대로 쓰며 자동 분류나 편집 기능은 없습니다.
