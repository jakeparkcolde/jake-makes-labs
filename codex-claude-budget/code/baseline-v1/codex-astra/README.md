# 차곡 · CSV 가계부

외부 API, 패키지, CDN 없이 HTML/CSS/JavaScript로 실행하는 한국어 가계부입니다. 파일은 서버로 전송하지 않고 브라우저에서 읽습니다. 입력 파일 `inputs/01-basic.csv`는 수정하지 않았습니다.

## 실행

가장 간단하게는 `index.html`을 브라우저로 열면 됩니다. **새로고침 후 저장을 일관되게 사용하려면 아래 로컬 HTTP 실행을 권장합니다.** `file://`에서의 저장 동작은 브라우저에 따라 다릅니다.

Python 3가 있는 환경에서 이 프로젝트 폴더를 현재 디렉터리로 두고 실행합니다. 패키지 설치는 필요하지 않습니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

1. `http://127.0.0.1:8000`에 접속합니다.
2. **CSV 파일 선택**으로 `inputs/01-basic.csv`를 올리거나 업로드 영역으로 끌어 놓습니다.
3. **조회 기간**에서 전체 또는 월을 고릅니다. 순지출·지출·환급 합계, 분류별 차트, 거래 목록에 같은 기간이 적용됩니다. 별도로 표시하는 ‘전체 누적 순지출’은 전체 데이터 기준입니다.
4. **CSV 내려받기**로 현재 기간의 거래를 저장합니다.
5. 서버 종료는 터미널에서 `Ctrl+C`입니다. 구현·검사 과정에서 백그라운드 서버를 실행해 두지 않았습니다.

같은 브라우저 프로필과 같은 주소·포트를 사용하면 업로드한 데이터, 파일명, 선택한 월을 `localStorage`의 `chagog.ledger.v1` 키에서 복원합니다. 비공개 모드 종료, 사이트 데이터 삭제, 저장 차단·용량 초과 시 유지되지 않을 수 있습니다. 저장 실패는 화면에 안내합니다.

## 입력 및 계산 규칙

- UTF-8 CSV를 사용합니다. BOM, LF/CRLF, 따옴표로 감싼 쉼표·줄바꿈·이스케이프된 따옴표를 처리합니다.
- 필수 열: `transaction_id,date,merchant,category,amount_krw,type`
- 선택 열: `original_transaction_id`. 열 순서는 자유이며, 추가 열은 무시합니다.
- `date`는 실제 존재하는 `YYYY-MM-DD`, `amount_krw`는 쉼표·통화 기호 없는 0 이상 정수입니다. 금액 및 전체 금액 합계가 JavaScript 안전 정수 범위를 넘으면 거부합니다.
- `type`은 `expense`(지출) 또는 `refund`(환급)입니다. 순지출 = 지출 합계 − 환급 합계입니다. 수입·이체·다른 통화는 지원하지 않습니다.
- 환급은 환급 레코드 자체의 날짜와 분류에서 차감합니다. 원거래 ID는 보존하지만 원거래와 자동 대조하거나 원거래 월로 환급을 옮기지 않습니다.
- 거래 ID가 중복되면 오류로 안내합니다. ID가 다른 거래는 날짜·가맹점·금액이 같아도 각각 집계합니다. 샘플의 `S05`와 `S09`도 각각 포함합니다.
- 차트는 분류별 순지출을 표시합니다. 막대 길이는 최대 절댓값에 대한 비율이며, 환급이 더 큰 분류는 음수 금액과 ‘환급 초과’ 문구로 표시합니다.
- 거래는 날짜 내림차순이며, 같은 날짜는 입력 순서를 유지합니다.
- 빈 파일, 거래 없는 파일, 필수 열·값 누락, 잘못된 날짜·금액·유형, 열 수 불일치, 잘못된 따옴표를 오류로 안내합니다. 실패한 업로드는 기존 거래를 변경하지 않습니다.
- 새 파일을 성공적으로 올리면 기존 데이터 전체를 교체하고 조회 기간을 ‘전체’로 설정합니다. 파일 병합은 하지 않습니다.
- 내보내기는 현재 필터의 거래를 정규화된 위 7개 열, UTF-8 BOM, CRLF로 저장합니다. 금액은 양수 원본 값과 `type`을 함께 내보내므로 재업로드 시 순지출 계산을 유지합니다. 추가 열과 셀 앞뒤 공백은 보존하지 않습니다.

```sh
node --check ledger.js
node --check app.js
node --check tests/ledger.test.js
node --test tests/ledger.test.js
```

- HTML의 JavaScript 참조 ID와 로컬 CSS/JS 경로, 모바일 viewport 및 반응형 분기 존재를 정적 검사했습니다.

## 한계 및 후속 브라우저 검수

**실제 브라우저 조작 검수는 이번 단계에서 수행하지 않았습니다.** 코드 테스트는 화면 렌더링이나 실제 다운로드·저장 성공을 보장하지 않습니다. 다음 항목은 후속 공통 절차에서 확인해야 합니다.

- 최초 업로드 안내, 파일 선택·드래그 업로드, 오류 안내, 실패 후 기존 데이터 유지.
- 8월·9월 전환 시 카드·차트·목록·내려받기 내용이 함께 바뀌는지.
- 같은 주소에서 새로고침 후 데이터와 선택한 월이 복원되는지. 저장용 JSON의 복원은 검사했지만 실제 브라우저 `localStorage` 동작은 미검증입니다.
- 실제 다운로드의 한글 파일명·UTF-8 내용 및 재업로드.
- **390px 폭**에서 가로 넘침, 금액·날짜·긴 가맹점 이름, 버튼 조작성. 반응형 CSS는 구현했지만 화면으로 확인하지 않았습니다.
- 키보드 포커스, 상태·오류 안내의 스크린리더 전달, 브라우저별 호환성.

현대적인 브라우저의 File API, TextDecoder, Blob, localStorage를 사용합니다. 대용량 파일은 전체를 메모리와 DOM에 올리므로 처리 속도·저장 용량에 한계가 있습니다. 다중 탭 사이의 실시간 동기화, 데이터 병합, 거래 편집은 지원하지 않습니다. 브라우저 저장은 암호화된 백업이 아니므로 필요한 기록은 CSV로 별도 보관하세요.

## 파일 구성

- `index.html`: 업로드 안내 및 가계부 구조
- `styles.css`: 데스크톱·모바일 화면
- `ledger.js`: CSV 입출력, 검증, 필터, 합계 계산
- `app.js`: 화면, 파일 선택, 브라우저 저장, 다운로드 연결
- `tests/ledger.test.js`: 외부 패키지 없는 기능 검사
- `inputs/01-basic.csv`: 제공된 원본 샘플
